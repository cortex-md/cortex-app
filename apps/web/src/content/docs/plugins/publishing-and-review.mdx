Publishing is release-asset based. The CLI tags a release, a GitHub Actions workflow builds and
publishes the assets, and Cortex installs the latest release of the repository listed in the
Marketplace registry.

## Release a Version

```bash
cortex check
cortex release patch   # or minor, major
```

`cortex release` runs the checks, bumps `version` in `manifest.json` and `package.json`, commits,
tags `v<version>`, and pushes. The release workflow scaffolded by `cortex create` then runs
`cortex pack` and publishes the GitHub release with its assets.

Versions are plain `MAJOR.MINOR.PATCH`; pre-release suffixes break update checks. Update detection
compares the `v<version>` release tag with the installed `manifest.json`.

## List in the Marketplace

```bash
cortex submit
```

`cortex submit` verifies the latest GitHub release, then opens a pull request to the Marketplace
registry. The registry entry has no version, so run it only for the first release and when the
name, description, author, or cover image change. Every later release reaches users automatically.

## Release Assets

The release workflow publishes:

```text
manifest.json      # with capabilities mirrored from permissions
dist/index.js      # or the basename/path referenced by manifest.main
styles.css         # optional, requires contributes.markdown
```

The CLI mirrors `permissions` into the release manifest's `capabilities` field automatically. Cortex
downloads `manifest.json`, reads `main`, then downloads the matching main asset. It accepts either
the exact relative path from `main` or the basename of that path.

## Manifest checks

Marketplace installation verifies:

- `manifest.json` is valid JSON.
- `manifest.id` matches the registry entry id.
- `manifest.main` is present and safe.
- The main bundle exists in release assets or in the source archive fallback.
- After install, the bundle loads and its `definePlugin` manifest id matches `manifest.json`.

`cortex check` runs the same checks locally before you release.

## Source Archive Fallback

If release assets are incomplete, Cortex can fall back to the GitHub source archive. It searches for
`manifest.json`, resolves the declared `main` file, and copies optional `styles.css` into staging.

This fallback is useful during early development, but published plugins should still include
release assets explicitly.

## Install and rollback behavior

Cortex installs into:

```text
<vault>/.cortex/plugins/<plugin-id>
```

Install and update use a staging directory. The previous plugin directory is preserved until the
staged plugin is promoted, the plugin host reloads, and the new plugin registration is visible. If
anything fails, Cortex removes staging and restores the previous plugin best effort.

## Votes, Downloads, and Review

Once listed, the Marketplace and the website show community signals for your plugin, published by
the registry's GitHub Actions:

- **Votes** are 👍 reactions on the plugin's Discussion in `cortex-md/registry`. "Vote on GitHub"
  in Cortex and on the website opens it; counts refresh every 30 minutes.
- **Downloads** add up the bundle downloads of every GitHub release, including updates.
- **Automated review** scans the latest release every day with the same static rules as
  `cortex check`. A failing release opens an issue and a proposed block for a maintainer to decide.
- **Verified** items are hand-picked by maintainers. **Pulled** versions stop being offered as
  installs or updates; installed copies are never removed automatically.

Run `cortex stats` to see all of this for your project. `cortex submit` also checks that you own the
repository, or are a public member of its organization, before opening the registry pull request.

## Release checklist

1. Run `cortex check` and fix every error.
2. Keep `main` relative and free of `..`.
3. Ship `styles.css` only when the plugin declares `contributes.markdown`.
4. Test install, reload, disable, and uninstall in a temporary vault with `cortex dev --vault`.
5. Run `cortex release` and wait for the release workflow to finish.
6. Run `cortex submit` the first time, or when listing details change.
