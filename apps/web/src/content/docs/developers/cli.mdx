The CLI covers the whole extension loop in five commands: `create`, `dev`, `check`, `release`, and `submit`. Each one detects whether the current folder is a plugin or a theme from `manifest.json`.

## Install

```sh title="Install the CLI"
npm install -g @cortex.md/cli
```

## Create

Scaffold a plugin or theme that loads in Cortex as-is. The template includes GitHub Actions workflows for checks and releases, a git repository, and installed dependencies.

```sh title="Create a plugin or theme"
cortex create word-count --plugin
cortex create sunset --theme
```

Run `cortex create` with no arguments for an interactive prompt. In an existing project, `cortex create --update-ci` rewrites only the workflows.

## Develop against a vault

`cortex dev` builds the project and copies it into `<vault>/.cortex/plugins/<id>` or `<vault>/.cortex/themes/<id>`, then rebuilds on every change. Cortex reloads it automatically. The vault is remembered for next time.

```sh title="Develop in a local vault"
cortex dev --vault ~/notes
cortex dev --once    # install once and exit
cortex dev --clean   # remove the development copy
```

The first time, turn on community plugins in Settings and enable your plugin. Plugin settings and `data/` in the vault are never overwritten.

## Check

`cortex check` builds the plugin, loads the bundle the same way Cortex does, and runs the checks the Marketplace registry applies: matching ids and versions, valid permissions, CommonJS output, stylesheet scoping, and release readiness. Every problem comes with a fix.

```sh title="Run every check"
cortex check
cortex check --strict   # fail on warnings too, used in CI
```

## Release

`cortex release` runs the checks, bumps the version in `manifest.json` and `package.json`, commits, creates the `v<version>` tag, and pushes. The release workflow then runs `cortex pack` and publishes the GitHub release that Cortex installs from.

```sh title="Publish a version"
cortex release patch
cortex release 1.0.0 --wait   # follow the release and offer to submit it
```

Versions are plain `MAJOR.MINOR.PATCH`. Pre-release suffixes break update checks in the app.

## List on the Marketplace

`cortex submit` verifies the latest GitHub release, then opens or updates a pull request to `cortex-md/registry` from your fork. The registry entry has no version, so you only submit once, and again when the name, description, author, or cover image change. Every later release reaches users automatically.

```sh title="Submit to the registry"
cortex login
cortex submit --dry-run
cortex submit
```

`cortex submit` uses `CORTEX_TOKEN`, `GITHUB_TOKEN`, the token stored by `cortex login`, or `gh auth token`, in that order. `cortex whoami` shows which one is active.
